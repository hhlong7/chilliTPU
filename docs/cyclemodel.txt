Part 1 builds the foundation of the cycle model: it describes the workloads, works out how long each piece of work takes on the array, and simulates the simplest policy (one network at a time). Here’s each piece.

1. Workload descriptions
Layer(name, M, K, N): one matrix multiply Y[M,N] = X[M,K] · W[K,N]. Convolutions are already flattened into this form (im2col). layer.macs gives the multiply count, M·K·N.
Network(name, layers, arrival): a list of layers that run in order, plus the cycle when the network shows up.
lenet5(batch): LeNet-5’s five layers as (M, K, N) shapes. The batch setting scales M, so you can test running several images at once.
2. Splitting a layer into passes

passes(layer, w) lists every pass a layer needs on a partition w columns wide, in the agreed order (N tiles outer, K tiles inner). A pass is one 12-row slice of K times one w-wide slice of N. For each pass it records w_eff, the number of columns actually used, which matters for the last, partial N tile.

Example: conv2 (100, 150, 16) on 12 columns needs ceil(150/12) × ceil(16/12) = 13 × 2 = 26 passes.

3. Timing of one pass

pass_phases(M, w_eff) splits one pass into three phases:

Phase	Cycles	What happens
load	12	weights shift down into the PEs
stream	M	input rows enter, one per cycle (the only phase that uses the feed port)
drain	12 + w_eff − 1	the last results ripple down and across and leave the array

They’re kept separate because part 2 needs to know exactly when a tenant is using the shared feed port.

4. Time for a whole layer

layer_cycles(layer, w, shadow) adds up all the passes:

Baseline (the paper): every pass pays load + stream + drain, one after another.
Shadow weights (our improvement): the next pass’s weights load while the current pass streams, so passes run back to back. Only the first pass pays the full load and only the last pays the drain.
5. Utilization

utilization(macs, cycles): useful multiplies ÷ (144 PEs × cycles). It shows what fraction of the array did real work.

6. Sequential policy

run_sequential(networks, shadow): the “no partitioning” baseline. Networks run one at a time on the full 12-column array, in arrival order. A network starts when it arrives or when the previous one finishes, whichever is later. It returns:

makespan: when the last network finishes
latency: each network’s finish time minus its arrival
util: overall array utilization
7. Self-test (--selftest)

It checks the code against the reference numbers worked out by hand:

each LeNet layer’s cycle count (2439, 3406, 12240, 2520, 238) and pass counts
one LeNet alone = 20843 cycles
two networks: the second waits for the first, and its latency is computed correctly
a late arrival leaves an idle gap
shadow weights never make a layer slower

Baseline vs shadow weights

Both describe how weights get into the PEs between passes. Each PE holds one weight. When a pass finishes, the array needs the next 12×12 block of weights before it can continue.

Baseline (what the paper does): stop, load, then compute.
Each PE has one weight register. To change weights, the array has to stop, shift the new weights in over 12 cycles, and only then start streaming inputs again. The array does no useful work during loading.

pass 1: [load 12][stream M][drain] 
pass 2:                            [load 12][stream M][drain]
pass 3:                                                      [load 12]...

Shadow weights (our improvement): load the next weights while computing.
Each PE gets a second weight register, the “shadow.” While the array computes with the current weights, the next pass’s weights shift quietly into the shadow registers. When the pass ends, every PE swaps shadow → active in one step, so the next pass starts immediately.

pass 1: [load 12][stream M]
pass 2:          [shadow-load during pass 1][stream M]
pass 3:                                     [shadow-load][stream M]...[drain]

The cost is one extra 8-bit register and a mux per PE (144 small registers in total), and no extra DSPs.

Why it matters so much for LeNet-5

In the FC layers, M = 1 (one image), so each pass streams for just 1 cycle but loads weights for 12. The array spends about 90% of its time loading weights. Hiding that loading is a large saving:

Layer	What it does	                                As a matrix multiply (M × K × N)
conv1	6 filters, 5×5, over the image	                784 × 25 × 6
conv2	16 filters, 5×5×6	                            100 × 150 × 16
fc1	    fully connected 400 → 120	                    1 × 400 × 120
fc2	    fully connected 120 → 84	                    1 × 120 × 84
fc3	    fully connected 84 → 10 (one score per digit)	1 × 84 × 10
