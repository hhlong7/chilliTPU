## Part 0: Decisions to lock first (~30 min, everyone)

Nothing else can be finished until these are agreed, because the golden model, the SV reference functions, and the RTL all depend on them.
Write each answer into `rtl/pkg/dnn_pkg.sv` + `sw/py/spec.py` (same PR) and `results/log.md`.

### D1. Requantize arithmetic
Proposal (exact, so Python and RTL match bit for bit):
```
s   = acc + bias                      # computed at 33 bits, no wraparound
r   = max(s, 0) if relu else s
p   = r * scale                       # scale: UNSIGNED 16-bit -> p fits in 49 bits signed
q   = (p + (1 << (shift-1))) >> shift if shift > 0 else p    # arithmetic shift: round half up (toward +inf)
out = clamp(q, -128, 127)
```
- [ ] `scale` width and signedness (proposal: unsigned 16)
- [ ] `shift` range (proposal: 5 bits, 0..31)
- [ ] Rounding: half up toward +inf as above (note: for negative values with relu off, -2.5 -> -2)
- [ ] `bias` width (proposal: INT32, added once per output, after the last K tile)

### D2. How many output-stage lanes (DSP budget)
`r * scale` is 33 x 16 bits, which needs **2 DSP48E1s** (the multiplier is 25 x 18).
- One lane per column: 12 cols x 2 = 24 DSPs → 144 + 24 = 168 at 12x12 (fits), but 196 + 28 = 224 at 14x14 (**does not fit 220**).
- One shared lane (or 2 lanes) that requantizes columns one after another during drain: 2–4 DSPs, slower drain.
- [ ] Decide: per-column, or 1–2 shared lanes (proposal: 2 shared lanes, parameterized `OUT_LANES`)

### D3. Tiling loop order (Python model, tile_ctrl, accum_mem all follow this)
Proposal: weight-stationary, **N tiles outer, K tiles inner, all M rows streamed per tile**:
```
for n0 in range(0, N, width):          # width = partition width (COLS for single tenant)
    for k0 in range(0, K, ROWS):
        load W[k0:k0+ROWS, n0:n0+width] into the array
        stream X[0:M, k0:k0+ROWS] through it
        accum[0:M, n0:n0+width] += tile result      # INT32, in accum_mem
    out[0:M, n0:n0+width] = requantize(accum + bias)
```
- [ ] Agree loop order
- [ ] Max M per layer (sets `accum_mem` depth). LeNet conv1 im2col has M = 784 → 784 x 12 x 4 B ≈ 37 KB: OK in BRAM.

### D4. Array timing and handshake
- [ ] PE latency = 1 cycle per hop (input right, psum down). Same for all PEs, so skew = row index.
- [ ] Inside the array: no valid/ready per PE; a single global `en` (stall) for the whole array. Valid/ready only at the array boundary (feed in, drain out).
- [ ] Weight load path: weights shift **down** each column over ROWS cycles on their own wires (not the psum wires), with a `w_load` enable. Leave a spot for a shadow weight register (`w_shadow`, `w_swap`) even if unused at first.
- [ ] Mul_En: one bit per column (from `part_ctrl`), registered into each PE.
- [ ] `PSUM_W` stays 32 for now.

### D5. Vector file format
- [ ] Hex: one value per line, two's complement, zero-padded to type width, row-major (already in the plan).
- [ ] Metadata for SV: `meta.txt` with `key=value` lines (`M=…`, `K=…`, `N=…`, `scale=…`, `shift=…`, `relu=…`, `seed=…`), plus `meta.json` for Python.
- [ ] Case folder naming: `vectors/<module or layer>/<case>/`, e.g. `vectors/out_stage/extremes/`, `vectors/layer/k_gt_rows_n_gt_cols/`.

### Track P2: `cyclemodel.py` (decides the headline improvement; Milestone 1 gate)
Model pieces, in order:
- [ ] **Workloads**: layer = (M, K, N); network = list of layers. Include MNIST-FC, LeNet-5 (im2col shapes), small CIFAR CNN, plus random networks. Arrival time per network.
- [ ] **Tile cost** for one (k-tile, n-tile) pass on a partition of width `w`: weight load (ROWS cycles, or 0 if shadow-loaded during the previous pass) + stream M rows + pipeline fill/drain (≈ ROWS + w − 1).
- [ ] **Feed model**:
  - (A) shared feed port: only one partition can stream inputs at a time, others wait (weight loads may overlap)
  - (B) per-partition feed: every partition streams independently
- [ ] **Policies**: sequential (one network at a time, full array), equal split (paper: `COLS / n_tenants`, first layer gets the whole array, merge on free), proportional (ours: `min(N_i, share by MACs)`, snapped to {2, 3, 4, 6, 12}, leftover to layers with passes remaining)
- [ ] **Event loop**: time advances tile by tile; partitions re-sized when a layer finishes or arrives
- [ ] **Metrics**: makespan, per-network latency, column utilization (busy column-cycles / total), MACs per cycle
- [ ] **Sweep**: ≥ 100 random mixes per setting, fixed seeds; also the "all layers similar" case (where we may not win)
- [ ] **Write-up** `results/cyclemodel.md`: does (A) cap the gains, by how much, and which improvement leads

Sanity checks to build in: sequential with 1 network = sum of tile costs; utilization ≤ 1; equal and proportional give the same answer when only 1 tenant is active.

## Part 2: RTL start (together)

### R1. `pe.sv` design on the whiteboard first (~30 min)
Agree on the ports before typing. Starting proposal:

| Port | Dir | Width | Meaning |
|---|---|---|---|
| `clk`, `rst_n` | in | 1 | clock, sync active-low reset |
| `en` | in | 1 | global array enable (stall when low) |
| `mul_en` | in | 1 | column's Mul_En (0 = add zero) |
| `x_in` / `x_out` | in / out | 8 | activation from left / to right (registered) |
| `psum_in` / `psum_out` | in / out | PSUM_W | partial sum from above / to below (registered) |
| `w_in` / `w_out` | in / out | 8 | weight shift chain (down the column) |
| `w_load` | in | 1 | shift the weight chain this cycle |

Behavior (every cycle with `en`):
```
x_out    <= x_in
psum_out <= psum_in + (mul_en ? x_in * w : 0)
if (w_load) w <= w_in;  w_out <= w   (shift chain)
```
- [ ] Check the multiply maps to one DSP48E1 (Yosys `synth_xilinx` gives a quick estimate on the Mac; label it an estimate)
- [ ] Decide reset values and what `x_out` does when `en` is low (hold)
